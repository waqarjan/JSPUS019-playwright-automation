# AI Agent Instructions for playwright-automation

## Project overview
- This repository is a Playwright automation test suite built with `@playwright/test`.
- Tests live under `tests/` and use ES modules (`type: module` in `package.json`).
- Primary runner configuration is in `playwright.config.js`.
- Environment variables are loaded with `dotenv` via `playwright.config.js`.
- Output directories such as `playwright-report/` and `test-results/` are generated by Playwright.

## How to run tests
- Install dependencies: `npm install`
- Run full suite: `npm run tests`
- Run headed tests: `npm run test:headed`
- Run debug mode: `npm run test:debug`
- Show HTML report: `npm run test:report`
- Run a specific test subset: `npm run test:specific`
- Run tagged tests: `npm run test:tag` or `npm run test:tag:headed`

## Test conventions
- Use `import { test, expect } from '@playwright/test';` in all spec files.
- Keep test files under `tests/` and name them `*.spec.js`.
- Tests are organized by day folders (`tests/day01`, `tests/day02`, etc.) and feature areas.
- Follow the existing file/feature structure rather than introducing a new layout.
- Do not leave `test.only` in committed code; `forbidOnly` is enabled on CI.
- Prefer Playwright selectors and built-in helpers over custom selector libraries.
- Avoid adding application backend code or infrastructure; this repo is strictly test automation.

## Configuration details
- `playwright.config.js` runs tests sequentially: `fullyParallel: false`, `workers: 1`.
- `forbidOnly` is enabled when `CI` is set.
- The Chromium project uses `channel: 'chrome'`, `viewport: null`, and launch args `['--start-maximized']`.
- Shared settings include `trace: 'on-first-retry'`, `screenshot: 'only-on-failure'`, and video capture on first retry.
- The config loads `.env` with `dotenv.config()` for environment variable support.

## Best practices for AI changes
- Modify or extend existing test files when fixing bugs or adding coverage.
- Keep changes aligned with existing Playwright patterns in this repo.
- If a new dependency is needed, confirm it fits the test automation scope and ask before adding it.
- Prefer concise, maintainable test code rather than large framework changes.

## Relevant files
- `package.json` — scripts and dependencies
- `playwright.config.js` — Playwright runner settings
- `tests/` — test implementation files
- `playwright-report/` — generated HTML report output
- `test-results/` — generated Playwright results output

## Agent Quick Tasks
- Install dependencies and run the full test suite: `npm install` then `npm run tests`.
- Run a single spec file: `npx playwright test tests/<path-to-file>.spec.js`.
- Open the HTML report: run `npm run test:report` or open `playwright-report/index.html`.
- Reproduce a failing run with verbose output: `npx playwright test --reporter=list --workers=1`.

## Local setup & troubleshooting
- This project uses ES modules (`type: module`) and loads `.env` from `playwright.config.js` — ensure `dotenv` and node are available.
- If Playwright or browser binaries are missing, run `npx playwright install`.
- Common issues: avoid committing `test.only`; CI enables `forbidOnly` which can fail runs.
